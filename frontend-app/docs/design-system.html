移动端设计系统
与交互标准

面向 PrismClaw 移动端的标准化设计交付物。统一颜色、字体、图标、弹框与反馈状态，确保所有交互场景遵循同一套设计语言。

01

颜色系统

颜色按「品牌 / 功能 / 中性」三层组织。品牌色只用于主操作与选中态；功能色只表达状态；界面层级由中性色与背景面构成，不靠阴影堆叠。

使用规则

推荐

  • 单屏一个主色操作：主按钮、选中态、链接共用 --primary，同屏填充主色块不超过 2 处。
  • 正文不用纯黑：正文 #1F232B，辅助 #575B62，弱化 #838C9E。
  • 状态色只做状态：成功、警告、错误色不用于装饰性图形或品牌表达。
  • 卡片优先描边：白卡用 --surface + 1px --line，阴影仅用于浮层。

禁止

  • 在同一视图混用两套主色（例如蓝色主按钮 + 紫色发送键）。
  • 用红色表达「删除入口」以外的强调，造成危险暗示。
  • 在 --bg 上直接放纯白大面积卡片而不加描边，层级会断裂。
  • 低于 11px 的正文使用 #838C9E，对比度不足。
对比度基线：正文与背景 ≥ 4.5:1；11–13px 辅助文字 ≥ 4.5:1；图标与背景 ≥ 3:1。禁用态可降至 3:1，但需同时配合透明度或状态文案。

字重与排版规则

字重

  • 400：正文、说明、长文本。
  • 500：辅助强调、标签、次级按钮。
  • 600：标题、卡片标题、按钮、弹框标题。
  • 700：仅用于 display 与数字强调。

行高

  • 标题行高为字号的 1.3–1.4 倍。
  • 正文行高 1.55–1.7 倍，中文长文取 1.7。
  • 单行控件（按钮、标签）使用固定行高，垂直居中。
  • 同一区块内行高统一，禁止 1.2 与 1.7 混排。

适配与截断

  • 系统最小字号 11px，低于 11px 仅用于角标且需高对比。
  • 标题单行省略；描述最多 2–3 行，超出 -webkit-line-clamp。
  • 数字使用 font-variant-numeric: tabular-nums。
  • 不通过缩放字号适配窄屏，改为截断或换行。
03

图标规范

全部图标采用 24×24 网格、线性描边、圆角端点。统一线宽 1.7，视觉重量一致；不使用双色、填充或 emoji 替代。

24px 网格与安全区

网格 24×24，内容安全区 20×20（四周留 2px）；圆角端点 stroke-linecap: round，转角 stroke-linejoin: round。

使用场景

导航与操作

返回、更多、加号、设置。默认 20–24，颜色继承文字色，主操作可用主色。

状态与徽标

成功、警告、失败使用功能色；仅图标不承载状态含义时使用 --text-sub。

列表与卡片

16–20，置于 36–40 的圆角容器中；容器圆角 12，图标与容器同心。

空状态

28–40，放入 --surface-3 的 44–56 容器；不叠加第二层装饰图形。

规范

  • 同一页面只使用一套图标族，线宽保持 1.7。
  • 图标与文字间距 6–8px，垂直视觉居中。
  • 可点击图标热区不小于 44×44。
  • 禁用态使用 38% 透明度，不更换颜色。

禁止

  • 同一行混用线性与面性图标。
  • 把 24px 图标缩放到 12px 以下使用。
  • 用 emoji 或位图替代系统图标。
  • 在功能色图标上再叠加阴影或描边。
04

弹框与浮层规范

按「是否需要用户决策」分为轻提示与模态弹框。模态弹框统一 320px 宽、24px 圆角、24px 内边距；底部操作固定，主操作唯一。

类型与适用场景

类型使用场景结构交互规则
Toast 轻提示操作成功、复制成功、提交反馈图标 + 单行文案，圆角胶囊不阻断操作，2.2s 自动消失；同屏最多 1 条
Alert 信息提示结果告知、权限说明、版本更新标题 + 说明 + 单个主按钮必须显式关闭；点遮罩不关闭
Confirm 确认操作暂停任务、切换工作区、放弃编辑标题 + 说明 + 取消 / 主操作默认焦点在取消；点遮罩仅非破坏性场景可关闭
Danger 危险确认删除会话、退出登录、停止运行标题 + 后果说明 + 取消 / 危险按钮禁止点遮罩关闭；危险按钮不使用主色
Form 表单弹框新建自动化、重命名、填写参数标题 + 1–3 个字段 + 取消 / 保存校验失败聚焦首个错误；有未保存内容时二次确认
Sheet 底部操作表更多操作、分享、选择来源拖拽条 + 操作项 + 取消点击遮罩关闭；危险项单独置底并标红
Full 全屏浮层复杂表单、文件预览、长列表选择导航栏 + 内容区 + 底部主操作独立页面栈；返回时校验未保存状态

视觉规格

尺寸

  • 弹框宽 320px（390 视口约 82%），最大 360px。
  • 圆角 24px，内边距 24 / 22 / 18。
  • 按钮高 42px，间距 10px；单按钮占满。
  • 表单字段高 40px，字段间距 12px。

层级

  • 遮罩 rgba(17,19,24,.42)，可选 2px 背景模糊。
  • 弹框阴影 0 24px 60px rgba(31,35,40,.18)。
  • z-index：导航 100 / 弹框 300 / Toast 400。
  • 底部 Sheet 圆角 24px 24px 0 0，含安全区内边距。

按钮层级

  • 每个弹框只允许一个主按钮（填充主色）。
  • 取消使用描边或文字按钮，置于左侧。
  • 危险操作使用 --danger 填充，文案写明后果。
  • 按钮文案使用动词，2–4 字优先。

交互演示

点击下方按钮查看标准弹框：信息提示、确认、危险确认、表单与底部操作表。

删除这条会话？
删除后会话记录与产出物将无法恢复，关联的定时任务不会受影响。

行为规则

必须

  • 危险操作必须二次确认，且默认焦点在「取消」。
  • 弹框打开后焦点锁定在弹框内，关闭后回到触发元素。
  • 表单弹框提交前校验；校验失败滚动并聚焦首个错误字段。
  • 异步提交时主按钮进入 loading 并禁用，防重复提交。

禁止

  • 一个弹框出现两个填充主按钮。
  • 用弹框承载超过 5 个字段的表单（改用全屏浮层）。
  • 危险确认点遮罩即关闭。
  • Toast 承载需要用户决策的内容。

操作反馈与状态

每个异步动作都必须有「进行中、成功、失败」三态；每个列表都必须有「加载、空、错误、离线」四态。状态出现在内容原位，不用弹框代替页面状态。

反馈规则

出现位置

  • 页面级加载 / 空 / 错误：内容区原位，占位高度不小于 160px。
  • 字段级错误：字段下方 6px，使用 11.5px 危险色。
  • 操作结果：Toast 或按钮内联状态，不使用阻塞弹框。
  • 网络状态：顶部内联条或页面级提示，不用 Toast 重复打扰。

行为

  • 超过 300ms 的请求才显示加载态，避免闪烁。
  • 失败必须提供重试或明确后续动作。
  • 成功提示不阻断下一步操作，2.2s 自动消失。
  • 同一错误不连续弹多个 Toast，合并为一条。

缺失节点类型标准做法

网络断开离线反馈页面顶部内联条 + 重试；恢复后自动消失，不弹 Toast。

落地顺序建议：先统一颜色与字体令牌（全局生效，风险最低），再接入弹框组件（危险确认 → 表单 → 操作表），最后逐页补齐加载、空、错误与离线状态。每接入一类，按本页验收清单回归一次。
