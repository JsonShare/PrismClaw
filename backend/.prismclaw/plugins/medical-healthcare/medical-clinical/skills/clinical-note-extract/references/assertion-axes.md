# 断言三轴规则（中文病历适配）

模型来源：ConText 正交轴模型（Harkema 等，*J Biomed Inform* 2009），后在 i2b2 2010 与 ShARe/SHARPn 中标准化。这里保留三轴独立性，换用中文病历的触发词表。

## 一、为什么必须分三轴

中文病历里，「糖尿病」三个字在下面每句中的含义都不同：

| 原文 | 真实含义 | 错误抽法 |
|---|---|---|
| 患者有 2 型糖尿病 | 现症 | — |
| 否认糖尿病 | 无此病 | 抽成「有糖尿病」 |
| 既往糖尿病 10 年 | 病史，可能已控制或停药 | 抽成现症 |
| 父亲有糖尿病 | 家族史，不是患者本人 | 抽成患者史 |
| 待排糖尿病 | 尚未确诊 | 抽成确诊 |
| 监测血糖，警惕低血糖 | 尚未发生 | 抽成「有低血糖」 |

单标签（如「negated: true/false」）会把「既往」和「家属」都压成「有」，信息就丢了。三轴各自独立，不做优先级合并。

## 二、presence（有 / 无 / 疑似）

默认 `present`。只有出现下列触发词才偏离。

### → absent（否定）

否定词（紧邻修饰时）：

- 否认、无明显、未见、未闻及、未触及、未引出
- 无、不伴、不伴见、排除、已排除
- 阴性、正常范围（对检查类）
- 「-」「（-）」「阴性」在检验单中的符号表示

覆盖范围：中文病历常用顿号列举，「无发热、咳嗽、咳痰」否定的是**三项**，不是只否定第一项。要一直延伸到句末或下一个肯定表述。

**陷阱：双重否定。** 「未排除结核」「不能除外肿瘤」不是 absent，是 `possible`。

### → possible（疑似 / 不确定）

- 可能、疑似、考虑、倾向、可疑
- 待排、待查、待除外、需排除、不能排除、未排除、不除外
- ？、？待查、性质待定
- 影像报告里的「不典型」「不典型增生」「建议随访观察」

**注意**：`consider`/「考虑」在中文病历里常表示「临床上按此处理」，比「疑似」强，但没有病理/确证依据。一律标 `possible`，并在 `notes` 里写明「临床考虑，未确诊」。

## 三、temporality（当前 / 既往 / 假设）

默认 `current`。只有下列情况才偏离。

### → historical（既往）

- 既往、既往史、曾有、曾患、患…多年、…病史 × 年
- 术后、已行…术、切除后、治疗后
- 已愈、已缓解、已停药、现已正常
- ×年前、×月前（用于描述已完成事件）
- 「s/p」英文缩写

**判断要点**：如果原文同时写了既往史和当前状态，**分两个字段或标两条记录**。例：「既往高血压 10 年，今测 145/90」——高血压 `historical`（或 `present` 若未停药，需看用药），血压值 `current`。

### → hypothetical（假设 / 预防 / 待排查）

- 预防、预防性、为预防…、应激性溃疡预防
- 监测、密切监测、警惕、注意有无
- 待排、需排除（与 possible 重叠时，temporality 取 hypothetical）
- 若出现、如发生、一旦…则
- 计划、拟、准备（尚未执行）

**为什么预防用药要标 hypothetical**：它是「为可能发生的事件」而用，不代表患者已有该诊断。把「奥美拉唑预防应激性溃疡」抽成「有应激性溃疡」是典型错误。

## 四、experiencer（本人 / 家属 / 其他）

默认 `patient`。

### → family_member

- 父亲、母亲、兄长、姐姐、弟弟、妹妹、子女、配偶
- 家族史、家族中、家系
- 「父母健在」「否认家族遗传病史」（后者 presence=absent + experiencer=family_member）

### → other

- 供者、捐献者、胎儿、新生儿（当病历主体是产妇时）
- 同事、邻居（社会史中提及）

## 五、组合判定示例

| 原文 | presence | temporality | experiencer | 说明 |
|---|---|---|---|---|
| 否认胸痛 | absent | current | patient | 单轴偏离 |
| 既往心梗史 | present | historical | patient | 单轴偏离 |
| 母亲乳腺癌 | present | current | family_member | 单轴偏离 |
| 未排除肺栓塞 | possible | hypothetical | patient | 两轴偏离 |
| 父亲疑似帕金森 | possible | current | family_member | 两轴偏离 |
| 母亲否认既往卒中 | absent | historical | family_member | 三轴全偏离 |
| 予低分子肝素预防血栓 | present | hypothetical | patient | 预防用药 |
| 拟行 PET-CT | present | hypothetical | patient | 未执行，另标 `planned` |
| 无家族遗传病史 | absent | current | family_member | 否定+家属 |

## 六、`planned` 补充标记

三轴不覆盖「是否已执行」。医嘱、计划、待办类表述，额外加：

```json
{"value": "胸部 CT", "span": "拟行胸部 CT", "presence": "present",
 "temporality": "hypothetical", "experiencer": "patient", "planned": true}
```

不加这个标记，下游会把「拟行」当成「已做」，所有基于「已完成检查」的推理都会错。

## 七、校验不过时的处理顺序

1. span 检索不到 → 先把换行、全半角、空格归一化后重试；仍失败说明值经过改写，必须回到原文取连续片段
2. 三轴取值非法 → 按本表重判，不要新增枚举值
3. null 无理由 → 补 `null_reason`；确实判断不了用 `ambiguous`，不要留空
4. 数值越界 → 先怀疑单位（mg/dL vs mg/L、% vs 小数），再怀疑抽取错位，最后才怀疑原文错
