# 按原文生成住院经历栏目草稿

适用于医生问某段住院经历放入哪个栏目，并要求可粘贴表述。归栏依据事件发生阶段，不以旧稿现有位置证明放置正确：入院背景与入院时状态归入院情况；本次住院后的转科、检查及治疗归住院诊疗经过。

先核附件可读事实，区分检查名称、检查所见与已实施治疗。接着把**本轮医生的原始叙述**原样保存为当前工作区source.txt；不把助手改写或OCR候选拼进医生原文。使用原文中的精确事实片段建立facts.json，字段如下：

```json
{"format":"hospital_course","facts":[{"section":"hospital_course","quote":"从本轮原文逐字选取的住院事件片段"}]}
```

这是字段示意，必须替换为本轮原文实际片段。需要同时保留入院背景时，可另加section=admission。仅改住院经历时不必新增入院段。不要把任务指令选作事实，不新增未给科室、目的、病理或操作名称。

```text
<已确认Python> <技能目录>/scripts/render_source_draft.py --source <当前工作区>/source.txt --facts <当前工作区>/facts.json --stdout
```

入口检查每条事实确为所选原文片段，拒绝把明确住院后事件放进入院情况；输出固定栏目建议及原文成稿。它不证明源文真实、附件识读正确或隐含时序已确认。最终采用同次输出的栏目与正文，不另写第二套临床事实。附件中的可读补充记录须进入同次可审阅交付并说明真实定位；不把未确认的检查名或示例术式放入草稿括号。

随后只列定稿必要的少量缺项，先排除本轮文字及清晰附件已给的信息。未给原科室只问“原科室”，不默认某专科；未给转科时点只问转科时点，不把检查记录时间自动当操作执行时间；病理等依实际是否取材条件列出，不补造已活检或已切除。未要求文件时用stdout结果直接回答，不强制文件交付。

## 同时采用文字与附件

需要保留附件中清楚的病情变化、日期或检查记录时，用`--source-bundle sources.json`替代`--source`。医生原话保存独立文本，附件仅转录已实际看清的片段到另一个文本；每份记录均保留身份，不能混写成医生原话。示意：

```json
{"sources":[
 {"id":"doctor","kind":"user_text","text_file":"doctor.txt"},
 {"id":"record","kind":"attachment_transcription","text_file":"visible-record.txt","attachment_file":"selected.png","region":[0,0,100,100]}
]}
```

区域须替换为本次原图真实像素范围。facts的每条添加`source_id`，引句只可来自该来源文本；附件可读片段由程序在对应栏目下单列，不把部分文字润色成完整术式或把记录日期推为实施日期。若有多个区域可分别建立来源条目。程序核原件哈希、区域边界及转录文本引句，**不证明文字识读正确**；必须实际查看原图/放大区域再使用。看不清的部分保持缺口，不复制OCR猜词。

清晰可读的记录时间应保留，随后只追问尚不明确的时点含义或实际操作时间，不再称整项日期未提供；病情变化的可读限定也保留。不抄录无关姓名、病案号或机构字段。最终缺项与所有已用文字/附件来源逐项去重。
