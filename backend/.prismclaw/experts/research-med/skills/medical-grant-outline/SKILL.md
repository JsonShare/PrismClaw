# 标书框架生成

把医生的研究想法、真实前期材料和申报要求，整理成可继续填充、可追溯、可编辑的框架。框架应说明每章要论证什么、已有何种依据、还需什么材料，而不只是列出目录，也不把缺失信息补成完整正文。

## 工作边界

- 发起医生是唯一流程用户和最终内容确认人。Agent整理、起草和提示问题；研究问题、设计选择、资源可行性及最终内容由医生确认。真实世界的伦理审批、试验注册、机构盖章等仍是待核实或待办理条件，医生确认草稿不等于这些条件已满足。
- 不编造前期成果、病例数、效应量、伦理批件、团队条件、预算价格、合作意向或申报规则；不承诺创新性、获批或申报资格。
- 只读取本任务允许使用的材料，先按下文明确读取范围。默认工作区可访问、文件名相似或先前任务曾使用，都不构成本次选定。患者资料只保留完成研究框架所需的去标识化信息；不把可识别信息放进公开检索、文件名或未经授权的外部工具。不代为发送、申报、签署或写回正式记录。

## 先确定本次任务

从请求和已有材料识别目标、项目类别/年度、任务范围及交付格式，不重复询问已知信息。

| 当前请求 | 执行方式 |
|---|---|
| 从研究想法生成框架 | 先凝练研究问题，再建立设计逻辑与逐章框架。只有方向时，先给通用结构和待选问题。 |
| 按通知/模板生成或调整 | 提取栏目和约束，按正式文件逐项映射；不擅自替换官方栏目。 |
| 检查或修改已有初稿 | 保留已确认内容和用户限定范围，指出问题位置、影响、依据与修改建议，再修订相关部分。 |
| 只改目录、格式或局部章节 | 只完成该部分；不强制生成全套材料或启动医学检索。 |

任务含多种合理解释且会改变交付物时，合并提出必要澄清。完整框架按下文执行；局部任务只执行相关步骤。完整生成或审查设计逻辑前，读取 [工作流程与输出规范](references/workflow-and-output.md)；准备调用工具时，按需读取 [工作台能力映射]（能力映射文档已移除，执行时直接检查当前会话可用工具）。

## 执行流程

### 1. 读取材料，明确依据

读取业务文件前，依据本轮请求和本任务已获确认的范围列出允许使用的输入：上传/选定的附件、医生明确指定的文件或目录，以及本任务中继续修改所必需的既有产物。已明确的范围直接沿用，不增加审批。目录内也只定位与请求有关的文件；不为“参考风格”“寻找示例”读取默认工作区里的其他任务文件。技能自身说明与参考文件、为当前主张检索得到的来源，按各自用途读取，不视为医生的前期材料。

新任务不自动继承其他任务文件的使用范围。缺少材料时先用占位继续；确需范围外文件时，说明用途并请医生选定后再读。若误读范围外材料，不将其纳入框架或来源依据，简要说明发生了额外读取及处理，不复述其中无关内容。

记录实际使用材料的名称、版本/日期、读取范围和缺页/不可读部分。按参考文件维护唯一的来源记录，正文与来源表共用稳定编号；不可在不同章节重新分配编号。

优先提取：研究主题和具体问题、研究对象/场景、初步假设、主要结局及时间点、项目类别/年度、目标评审类型、真实前期基础与资源、周期、预算边界、通知/模板和交付要求。材料未载明的信息保持未知；“没提供”不等于“没有”。伦理等事项分别记录材料提供情况、申请进度、审批结论及各自依据；只缺批件时写“批件未提供；是否申请、是否获批未知”，不得补成“未申请”“未获批”或“批件不存在”。医生明确说明的状态按自述记录，未核对证明材料时注明限制。

多轮修订仍回溯医生材料与陈述；助手自己上一轮的结论、旧稿和自检声明不构成新的事实依据。拒绝虚构事实时，替代写法也只能采用已有事实或未知状态。只改标题等局部任务保持原文范围，但交付说明不能把未经复核的旧内容再次确认为事实。

只有需要判断时效、当前申报状态或“未来年份”时才核定当前日期：使用本轮可信的运行时间或实际时钟读数，记录来源；取不到时保持未知，不能凭记忆写会话年份。文献年份、申报年度与当前日期分别记录；当前年份不自动替换医生指定的历史项目年度。

有通知时，将标题与层级、字数/页数、格式、资格、日期、附件、预算限制和评审要求拆为可独立判断的约束，保留原文定位。每项分别记录“已明确/未载明/存在冲突”和落实位置；正文、篇幅规划、缺口清单都从这份记录生成，不能把已明确要求再次写成未知。按适用的正式通知、模板及补充说明组织框架；版本冲突不能自行合并为一套“官方要求”。无通知时用通用框架，显著标明“待按具体申报通知调整”。

### 2. 分清可继续的缺项与需医生决定的事项

- **可以继续：** 未提供通知、预算明细、前期数据、团队履历等，仍可完成通用目录、材料清单、论证位置和占位提示。缺少通知不妨碍通用起草，但不能宣称符合某项目要求。
- **暂停受影响部分：** 未确定的研究对象、主要结局或设计选择会改变方法学链条；材料冲突会改变申报口径或可行性；使用范围或隐私授权不清。说明“缺什么—影响什么—需要医生补充或选择什么”，等待回答后再确定该部分；同时继续不依赖它的整理。
- 不用“已脱敏”“已有伦理审批”“病例充足”等假设跨过事实缺口。可提出备选问题、设计或资源调整建议，但标为建议并交医生选择。提问不必阻止交付带占位的框架草稿。
- 研究方向、主要结局等已获确认且无新冲突时直接沿用。只有将开展高成本扩展生成（如整篇扩写或图像生成）时，才先展示对应结构和范围等待确认；普通框架起草不增加逐步审批。

### 3. 建立研究逻辑，再组织章节

需要从指南推荐或临床量表形成研究问题时，先核对所用版本、原始条目及适用条件；涉及临床适用性判断时交临床诊疗专家出具，本包据此形成研究问题。拟定结局操作定义或分析方案时，加载 `medical-manuscript-writing` 的研究方案分支。本轮已读来源和已核条件直接复用，按用户要求交付研究问题或相关章节。

按参考文件建立“研究问题—假设—目标—对象/设计—结局及时间点—分析思路—资源”对应关系。每项目标都要有能回答它的设计与可测量指标；标出无法闭合的环节。

设计未定时比较可选方案的适用条件、所需资源及局限，不替医生选定。样本量未确定时只列估算所需参数及来源缺口；无依据不填例数、效应量、检验效能或其他参数。不把前期病例数直接当作拟入组样本量，不把观察性关联写成确定的因果或机制结论。

### 3.1 核对估计目标、时间与可证伪命题
涉及队列或观察性设计时，先定义研究对象、time zero、暴露测量窗、结局窗、目标估计量和分析人群，纳排标准不能依赖尚未发生的结局。偏倚方向仅在明确机制和条件下解释，不把某类时间偏倚固定称为同一方向。

核心实验逐项列目的、模型/选择标准、干预、匹配对照、读出和预先判据。机制链每条箭头都明确对象和证据层级，区分关联、必要性、救援与充分性；必要性或炎症背景下救援不能自动证明无炎症背景下充分性。依主张考虑基线、非特异性、残留刺激、交互、匹配回补及替代解释对照；只写与当前命题有关的对照，不把所有实验泛化为固定套餐。未显著不等于等效，也不直接否定机制。

既往研究比较应覆盖主要结局、随访及分析，研究空白不能只靠题目不同。探针、治疗方案、耐药/疾病模型操作标准未确定时，只暂停受影响的验证设计，保留框架和待选方案；不得在章节之间更换分子、模型或术语含义。

### 4. 按需补充证据

研究背景、疾病负担、现行标准、研究空白、创新性比较和方法学论据需要可追溯依据；纯结构映射和格式修改无需新增医学检索。只请求框架时，先列论证位置与证据需求，不为充实章节而主动写成含未核验数字的背景段落。

- 医学证据先使用实际可用的内部医学检索；内部能力不可用或结果不足时，才按权限补充公开检索。把任务拆为明确主张，不以整篇标书为模糊检索问题。
- 项目规则查适用年度的官方通知、模板及更正说明，不用医学知识库或聚合转载替代。涉及当前申报状态、截止时间或资格，且公开检索可用时核验官方来源；无法核实时写明版本和未核验范围。
- **先核验，再决定能否进入论证内容。** 为关键外部主张记录来源定位、允许使用的表述、适用限制与状态，按参考文件区分“可用于论证”“候选待核验”“冲突/不支持”。只有实际读取原始来源相关内容、核对该主张及限定条件后，才能转为“可用于论证”。来源看起来权威、带链接或返回节选，都不能替代此判断。
- 正文、各章“已有依据”、创新性与风险表、设计参数以及会话总结，共用这份主张记录。**候选或冲突项不进入这些位置作事实论据**；相应位置只保留不含候选数值的论证占位。确需展示候选数字或推荐时，只在独立的“候选证据（未用于论证）”区逐条列出状态与核验动作；不能在其他位置重述后仅加“待核验”括注，也不能把它称为“已有证据支撑”。
- 可编辑文件使用稳定来源编号，并提供实际取得的标题、版本、原文链接/DOI等可定位信息；应用内部引用标记可以保留，但不能是唯一追溯方式。无法取得可定位信息时注明缺口，不猜链接、DOI或页码。具体记录与导出检查见参考文件。
- 区分“资料已有事实”“外部来源事实”“建议/推断”“待补充/待核验”。保留证据分歧；检索不到不等于不存在，也不能据此宣称“国内外首创”。

### 5. 起草可填充框架

完整交付结构及逐章模板见 [输出规范](references/workflow-and-output.md#交付结构)。按官方栏目组织；没有通知时采用通用栏目并说明适配状态。对每章写出论证目的、建议内容、已有依据和需补充材料，给出技术路线文字描述，以及风险、伦理、进度和预算待确认项。

默认提供可复制编辑的 Markdown。医生指定 Word 等格式时，先确认实际生成能力；仅在文件真实生成、检查成功后报告对应格式。生成内容、生成文件和交付文件是不同状态，不以工具名称推定成功。

### 6. 自检并交付

本任务提出新的研究问题与设计时，加载 `medical-manuscript-writing` 完成研究方案成品审阅；已加载该技能时直接复用其审阅流程。原始要求、实际成品及本轮已读来源供审阅者核查，依据具体发现修订后再交付。只改申报目录或格式时，检查本次修改范围。

交付前回读最终产物，按参考文件完成与本次任务相关的检查；局部修订仅检查修改范围及受影响关系：

- 栏目、篇幅、附件是否与通知约束逐条一致。若给出数值篇幅建议，实际计算子项合计、栏目分配及正文总分配，分别核对上级预算和通知上限；篇幅规划检查不能冒充全文字数已达标。已明确条款不得重复出现在未确认清单。
- 目标、设计、主要结局、分析和资源是否对应；跨章节的对象、样本、时间、术语是否一致。
- 从最终产物逐处反查关键事实/数字到主张记录；候选数值和推荐是否泄漏到章节、表格或会话总结，来源是否支持相邻主张。发现泄漏则移回候选区、恢复正文占位，不以“表中已注明待核验”为由保留。导出引用须能脱离应用定位来源。
- 所用材料是否在允许范围内，交付说明是否如实描述实际依据；是否混淆拟开展工作、真实前期工作和预期成果。
- 材料提供、申请进度和审批结论是否各有依据、未知是否仍保持未知；时间判断是否有本轮日期来源；是否包含不必要的患者识别信息。
- 提取最终标题清单，核对“见某节”和标题链接是否存在且指向意图相符的内容。可用 Python 时运行 [文内引用检查脚本](scripts/check_internal_refs.py)，按参考文件说明处理结果；它只检查支持的文内引用格式，不验证证据或事实。
- 声称生成的文件是否实际存在、内容可读；声称完成的校验是否真实执行。

发现事实状态无依据、候选主张被当作事实、编号错配、篇幅超限或通知矛盾时，先修正再交付。原文不可读等外部限制不阻止交付带占位的框架，但不放行对应主张。自检说明只能来自最终回读与实际检查结果：脚本通过、文件非空或有核验表，都不能概括为“事实已核验”“所有引用准确”或“全部通过”。

交付时简要列出产物、依据范围、已完成检查、工具限制及待医生确认事项。内容未确认时标记“草稿/待医生确认”；明确区分“框架已生成”与“申报材料已完备”。医生确认后也不推定获得机构审批或可以自动提交。

## 异常处理

- 源文件缺页、图表未识别或读取失败：指出文件/位置及影响，交付已确认部分，请医生补充可读内容。
- 工具缺失或无权限：采用能力映射中的降级方式；不编造调用、文件、引用或成功状态。
- 失败后仅在可纠正参数或已知临时故障时做有限重试；重复失败则停止该步骤，保留已完成内容并说明缺口。
- 资源不足或设计无法回答目标：明确问题和可选调整，等待医生决定受影响部分，不以润色掩盖。
- 要求编造事实或超出本技能范围：说明该部分不能完成，继续交付范围内的可用框架。
