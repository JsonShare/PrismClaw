# 工作流程与输出规范

用于完整框架生成、申报模板映射和研究设计一致性检查。局部修改只使用相关部分；以下栏目是通用备用结构，不是任何项目的官方格式。

## 输入分级与任务分支

| 输入状态 | 可以先完成 | 需要医生补充/决定后才能确定 |
|---|---|---|
| 只有研究方向 | 通用目录、待凝练问题、所需输入 | 具体问题、对象/场景、主要结局和设计 |
| 有研究问题，无申报通知 | 研究逻辑草案、通用逐章框架 | 特定项目栏目、资格、篇幅与申报日期 |
| 有通知/模板 | 逐条提取约束、映射和篇幅规划 | 冲突版本、含糊条款、缺失附件 |
| 有初稿 | 按范围检查并修订；保留已确认设计和事实 | 会改变科学问题、主要结局或设计的选择 |
| 前期基础/预算/团队材料不足 | 章节占位、证据清单、成本类别 | 前期成果、资源可行性、具体金额和承诺 |

将必要澄清合并提出，优先询问会改变后续框架的选择。允许排版、编号等低风险默认设置；研究事实、资源和方法学参数不设无依据默认值。

## 来源与约束记录

### 材料范围与来源编号

允许使用的业务材料按“文件/目录或会话产物—选定依据—本次用途”记录，已有明确输入不必要求医生重复确认。任务目录只限定可查找范围，不意味着目录内所有历史文件都要读取；共享工作区里的旧产物不能自动作为风格样例或前期基础。

输入材料用 `M1、M2…`，外部证据用 `E1、E2…`。先登记再引用：同一材料与版本使用同一编号；新增来源追加编号，不因章节顺序改变已有编号。不同版本分别记录。正文与来源表引用同一份记录，不分别生成两套映射。仅引用实际读取的内容，定位精度不超过工具提供的精度。

| 编号 | 材料/来源名称 | 年份、版本或日期 | 可定位信息 | 本次读取范围与来源类型 |
|---|---|---|---|---|
| 按实际材料填写 | 文件名或来源标题 | 未知则注明 | 附件及页/节/块；外部来源的实际URL/DOI等与具体位置 | 如原文相关段、摘要、知识库节选、转载或生成报告；缺页/图表未读须注明 |

同批涉及示范病例、前期研究、讨论示例和拟议项目时，在这份记录补充材料的所属对象、真实/授权合成/计划假设性质与允许用途，不另建一套来源编号。合成授权只作用于明确指定的对象；示范病例、示例讨论及助手生成的论文不能作为申请人的真实前期基础。

引用本批统计输出时保留实际运行对象、方法及未执行范围，不能把分析计划写成已完成成果。缺少本中心比例、检测平台、样本库、团队或合作材料时，前期基础保持未提供，研究方案可列资源需求或明确标注的规划情景；不把文献比例或规划参数称为本中心既往数据，也不因为PPT或旧稿已这样写就转为已有条件。核对最终正文、技术路线及配套PPT中的每项既有资源声明，而不仅检查缺口表。

### 项目事实与办理状态

材料情况与现实状态分开记录，未获依据的字段保持未知。用于伦理、注册、数据授权等本次相关事项即可，不要求简单任务增加整张表。

| 事项 | 材料提供情况 | 申请进度 | 审批结论 | 每项状态的依据 |
|---|---|---|---|---|
| 按任务填写 | 未提供 / 已提供但未读取 / 已读取及范围 | 未知；或有依据的未申请、已提交、审查中等状态 | 未知；或有依据的批准、补正、未通过等结论 | M编号与原话/位置；区分医生自述与证明材料，无依据则未知 |

- 仅说“未提供批件” → “证明材料未提供；是否申请、是否获批未知”。不能写成“未申请”“未获批”“尚未办理”或“批件不存在”。计划“拟于启动前核实/办理”不代表目前尚未申请。
- 医生说“已经获批，但未上传批件” → “医生自述已获批（M编号）；批件未提供，尚未核对”。不能无视已提供的自述，又不能升级为批件已核验。
- 只有医生陈述或材料明确记载“尚未申请”时才记录未申请；收到批件并读取后按其内容记录，不推断覆盖了未载明的研究范围。
- 以上规则同样用于回复、替代写法与后续修订。旧稿中已有无依据状态时，在涉及该事实的修订中纠正；纯标题修改不扩大正文修改范围，也不重复背书旧状态。

### 关键主张的使用状态

仅在实际采用外部医学/方法学主张时维护下表，可与来源记录合并。先登记和核验，再写论证内容；没有足够依据时交付证据需求与占位，不强制凑齐背景事实。

| 主张编号 | 主张或待论证问题 | 来源及实际读取依据 | 使用状态 | 允许表述/下一核验动作 | 最终使用位置 |
|---|---|---|---|---|---|
| K1、K2… | 每条有独立限定条件的主张 | E编号、原文定位、实际读取内容与范围 | 可用于论证 / 候选待核验 / 冲突或不支持 | 已核验者保留人群、时间、结局与适用边界；其余列具体核验动作 | 精确到章节/表格；候选仅定位到候选区 |

| 状态 | 进入该状态的条件 | 可出现的位置与形式 |
|---|---|---|
| 可用于论证 | 已读原始来源相关内容，核对来源版本与主张一致、限定条件适用，记录实际读取依据 | 在范围内用于正文、已有依据、创新/风险表及总结；引用相同E编号与原文定位 |
| 候选待核验 | 仅有标题、摘要、知识库节选、转载、生成报告，或缺原文定位/必要条件 | 数字、阈值和推荐只列在“候选证据（未用于论证）”区；正文相应位置只写证据需求，不复述该候选断言 |
| 冲突或不支持 | 来源不支持拟写主张，或矛盾尚未查明 | 列冲突/问题及核验动作；不选择有利结论作为事实 |

“可用于论证”针对某条主张，不代表整篇文献全文读完或全部有效。若关键条件未确认，仍为候选；不能用“节选已读”代替状态判断。通过更多检索、医生认可框架或复制上一稿，均不能自动升级核验状态；只有完成缺失的读取与核对后才更新。

**占位写法示例（不涉及真实医学结论）：** 候选区可记“某二次来源报告效果数值X，待核原研究及适用人群（K2）”；正文写“[待补证据：该策略对目标结局的效果及适用人群，见候选K2]”。不要在正文写“该策略改善目标结局X（待核验）”，也不要在风险表或总结中重述X作为既定依据。

交付前以最终文件为准检查两次：从正文/表格/总结的关键事实反查可用主张；再从候选项反查其数值、来源编号及语义是否出现在论证内容中。文本搜索可帮助定位，但须读取上下文，数字未出现不等于没有以文字复述。发现候选泄漏，移回候选区或删除断言并保留论证占位。无可用外部证据时，“已有依据”写明暂无已核验外部依据，不把候选集合写成“证据已齐备”。

### 导出引用

- 正文引用采用稳定编号，例如“……（E1，原文§3）”；用“原文”区分来源定位与本文件章节。来源表给出实际取得的标题、年份/版本、链接或标识符及定位。若只拿到二次来源链接，标明“二次来源”，原文定位保持待补。不得据标题拼接URL、编造DOI或页码。
- 应用内的 `[ref:…]` 等标记只能作为附加交互引用。导出时将其对应到稳定来源编号；不能解析对应关系的标记不充当证据，改为待核验占位。不能仅留下内部ID让医生自行猜对应来源。
- 回读最终文件，逐处核对编号、材料名称/版本与所支持的主张；不是只检查“编号在来源表中存在”。“期刊网站页面”等泛称不能作为可定位信息，具体地址或标识符未取得时注明缺口。

### 日期依据

时效判断所用的“当前日期”须记录本轮运行时间或时钟工具结果及来源；工具返回时保留时区。助手记忆、上一稿所写年份、材料发布日期均不是当前日期。取不到可靠时间时，写“当前日期未核定，时效待核实”，不据此判定文献来自未来或通知已过期。

医生指定的申报年度、文献标注年份和当前日期是三个不同字段。年份异常时核对出版/在线发表等实际元数据，不以错误或未知的当前年份宣布来源无效，也不把实际出版状态当成已确认。

### 本文件章节与标题引用

先定标题，再生成交叉引用；来源的页/节号与本文件编号分开标注。最终改动标题或顺序后，提取实际标题清单，检查本文件的“见3.6”“见七、交付说明”等每个定位：目标存在、编号与标题对应、内容能回答引用目的。不能通过统计标题出现次数宣称全部引用正确。

具备 `Bash` 与 Python 3 时，对最终交付文件运行技能内的 [文内引用检查脚本](../scripts/check_internal_refs.py)：

```text
python3 "<实际技能目录>/scripts/check_internal_refs.py" "<最终交付Markdown文件>"
```

脚本只读指定文件，不扫描工作区、不修改产物、不联网。它检查以`#`标记的标题对应的Markdown锚点链接、明确的“见/参见/详见 数字节号”和引号内带编号的完整标题引用（末尾括注可省略）；忽略代码块与行内代码。锚点采用常见的GitHub规则，自定义锚点、其他标题/引用格式需手工核对。返回错误位置，退出码1表示发现目标错误，2表示参数或输入不可用。修正这些错误后重跑；零错误只表示支持的语法中未检出目标问题。其余定位、目标内容是否相符以及医学证据、伦理状态、日期和篇幅仍需单独核对。无运行能力时按标题清单逐项核对并说明未运行脚本，不据此停止可交付的框架整理。

### 通知约束与待确认事项

正式通知约束另建映射。把可独立判断的事项分开记录，保留官方栏目原名与层级：

| 要求编号 | 要求原文或准确摘要 | 来源及位置 | 约束状态 | 落实位置与检查结果 |
|---|---|---|---|---|
| 按实际条目填写 | 明确数值、单位、适用范围和例外 | M编号或官方外部来源及位置 | 已明确 / 未载明 / 存在冲突 | 对应栏目/附件；已落实、需修正或待补信息 |

- 区分正文、表单和必交附件。预算比例、资格、日期等逐项追溯；资格只做文件条件与已提供信息的对照，不宣称已完成官方资格认证。
- 栏目、内容映射、篇幅和待确认清单共用这份约束记录。已明确的许可或限制不能再列为未知；医生材料尚缺与通知规则未知分开记录。例如“允许独立辅助清单”与“图表是否计入字数”是两项，后者未载明不能推翻前者。
- 要求与建议分开：通知未规定章节长度时可给“建议篇幅”，不得写成官方限制；预留修订余量也是建议。上限之和等于总限额时，不能据此推导出“禁止各栏写满”。
- 多份通知/模板冲突时记录各自发布方、年度、版本和位置；只有适用的官方更正或替代关系明确时才更新依据，否则向医生确认。

### 篇幅计算

只有给出数值分配时才做分配求和；没有数值建议时直接保留通知上限。只修改标题等局部任务，不重建全篇篇幅规划。

1. 从最终框架提取每栏上限、建议分配及全部子项分配，与同一约束记录核对。总览中的分配与逐章细项须一致；改变一处后同步另一处。
2. 实际计算 `子项合计 ≤ 该栏建议分配（若有）≤ 该栏上限`，以及 `正文各栏分配合计 ≤ 正文总限额`。区间建议按上界检查；正文计数中的标题、表格等按通知口径纳入，未知口径单独标待核实。不能只把官方上限相加就声称检查了建议分配。
3. 可用 `Bash` 时对最终数列求和并保留结果；无执行能力时列出算式逐项核对，不能声称运行了脚本。发现超限先调整分配，修正后重算。例如某栏限1200字，子项合计1300字时，不能在交付说明中标为已通过。
4. 区分“规划预算满足上限”与“实际正文符合字数”。框架中的说明、映射和辅助清单不自动算作拟提交正文；只有实际正文和计数口径确定并完成计数，才能声称正文字数已达标。单词、字符、字节和中文字数不可混用。

## 研究逻辑检查

先用一句话表达待研究问题：在什么对象和场景中，拟研究什么干预、暴露、机制或预测任务，针对什么结局或可测指标及时间范围。临床问题可用PICO/PECO等结构辅助；基础、机制、诊断或预测研究按任务调整，不强行套用同一结构。

| 目标编号 | 研究问题/假设 | 对象、设计与比较方式 | 主要/次要结局及测量时间 | 数据来源与分析思路 | 真实资源依据/待确认 |
|---|---|---|---|---|---|
| 每项目标一行 | 假设须可检验；探索性任务可注明暂不设验证性假设 | 已确认或备选，不能混写 | 未定则占位 | 说明如何回答目标 | 对应来源编号或缺项 |

按研究类型检查与当前范围相关的项目：

- 临床观察/干预：研究人群、纳排边界、对照、时间顺序、随访、主要结局和偏倚控制能否支撑目标；研究设计是否被不当地写成已定。
- 诊断/预测：目标用途、参照标准或预测时点是否清楚；验证数据与建模数据是否区分，是否存在数据泄漏风险。
- 基础/机制/转化：模型/材料、比较与控制、可测指标、关键验证环节及向临床外推的边界是否对应。
- 样本量：先明确估算目的/方法，再列所需参数及其来源，例如主要结局、效应或精度、变异/发生率、显著性水平、效能、分配方式、失访或设计效应。只列适用项；参数不足则保留“待估算”，不填示例数冒充项目数值。
- 若医生要求且数据、参数和计算能力齐备，可估算样本量，但须保留公式/方法、参数来源、假设、实际执行结果及限制。现有样本数、预期可获得样本数和估算所需样本数分别记录。
- 分析思路与结局类型、比较目标和设计相符；缺失数据、混杂、重复测量或多重比较等仅在适用时提示。不要机械堆砌统计方法名称或展开为未请求的统计分析任务。

未闭合处按“位置—问题—影响—已有依据—需医生选择/补充”列出。不得为了让表格完整，补造研究对象、事件率或设计选择。

## 交付结构

完整任务默认包含以下内容；官方模板可改变章节顺序和名称。辅助映射、材料清单和待确认项可放在框架之后，避免插入官方表单的错误位置。

### 1. 状态与适用范围

写明“框架草稿/待医生确认”、项目或研究主题、采用的通知/模板版本、所用材料范围、尚未核验的事项。无通知时显著写明“通用框架，待按具体申报通知调整”。

### 2. 申报栏目映射与篇幅规划

按上文约束表输出。有通知时逐项对应；无通知时写“暂无正式通知，以下为建议栏目”，不生成虚构的官方要求。篇幅建议应标识为建议；不用固定比例冒充评审标准。

### 3. 研究逻辑与逐章可填充框架

给出研究问题、假设和目标概述及对应关系表，再按以下模板写每章。每章包含实质性的写作方向，不能全部只写“待补充”。

```markdown
### [官方栏目名；无通知时用建议栏目名]
- 本章目的：需要向评审说明或论证的问题。
- 建议结构与要点：与本课题相联系的子标题及内容提示。
- 已有依据：来源编号与位置；未提供则明确写出。
- 待补材料：[待补充：具体材料或参数；用途：支撑哪个论点/决定哪项设计]
- 需确认的选择或证据不足：具体问题及其影响。
- 篇幅/格式：官方限制及出处；或明确标为建议/未载明。
```

无正式模板时，从下列栏目选择适用项并按课题调整：

| 建议栏目 | 应体现的内容 | 没有来源时不得补写 |
|---|---|---|
| 项目名称与摘要骨架 | 对象、核心问题、研究思路与预期价值；题名可给建议 | 已实现的疗效、机制或成果 |
| 立项依据与研究现状 | 临床/科学问题→已有证据→尚存不足→本研究切入点 | 未核实负担数据、未经检索的“空白” |
| 科学问题、假设与研究目标 | 可检验关系、总体与具体目标及可测结局 | 医生尚未选定的核心问题/结局 |
| 研究内容与方案 | 对象、设计、分组/比较、测量、样本量依据、分析与质控 | 病例数、效应量、现成数据、既定方案 |
| 技术路线 | 从材料/对象到研究步骤、测量、分析、验证及目标的连接 | 尚不存在的实验结果和平台能力 |
| 创新点与预期贡献 | 与已有工作的具体差别、证据及待验证之处 | “首创”“填补空白”等无依据断言 |
| 前期基础与工作条件 | 已有工作、团队、平台和合作条件与本课题的关系 | 未提供的论文、预实验、设备、合作承诺 |
| 进度与预期成果 | 阶段、里程碑、依赖、预计交付；成果写成目标 | 保证阳性结果、发表/授权承诺 |
| 风险、伦理与数据管理 | 科学/实施风险、应对、审批/注册适用性、数据保护 | 已获批/已注册/已获知情同意的状态 |
| 经费框架 | 成本项与任务关联、测算依据及待核金额 | 无依据价格、比例和经费标准 |
| 参考依据与附件 | 实际引用来源、按通知要求列材料 | 不存在的引用、证明或附件 |

### 4. 技术路线文字描述

明确各步骤的输入、工作、输出以及对应目标，并标出依赖或待决定节点。例如可用“对象/材料获取→分组或测量→分析→验证→回答目标”的文字链，按课题调整。避免把并行任务强行写成串行，或画出研究尚不支持的因果链。

默认文字即满足交付要求。仅在医生要求且工具可用时生成图形；生成前确认结构，生成后核对文字、箭头、分组和数字，不把图像生成等同于方法学验证。

### 5. 实施、材料缺口与待确认项

- **进度：** 按项目周期列阶段、任务、产出和前置条件。周期未知时给阶段顺序而不编造月份；建议时间明确标为建议。
- **风险：** 列风险及影响、已有依据、备选措施和需医生决定的事项。资源不足要显式保留。
- **伦理/注册/数据：** 根据是否涉及人体干预、样本、既有数据、动物等列适用事项或“适用性待确认”，不一律宣称已豁免/必须注册。涉及受试者时列知情同意或豁免依据、受试者保护与风险处理；数据部分列去标识化、访问权限、存储与使用范围。沿用上文独立状态记录，不因缺批件推断办理进度；未知项列待确认。
- **经费：** 以任务对应成本项，列测算依据、来源、金额待确认和通知限制。没有报价时不填价格；已给定总额时检查一致性，不为凑总额编造分项。
- **缺口：** 汇总逐章缺失材料并去重；为每项标明对应章节/目标、影响、需要医生提供或选择的内容。区分“影响研究设计/项目适配的关键项”和“可在扩写时补充的材料项”。

### 6. 交付说明

交付说明从最终产物和实际检查结果生成，不能直接复制起草计划或上一轮自检。概括实际材料范围、已完成内容、格式和待确认项；相关检查分别说明：通知映射、篇幅计算、主张使用状态、事实状态依据、文内定位、文件可读性。只做过数字求和、标题扫描或文件存在检查时，不将结果扩展为证据核验或全部事实无误；未核验事项具体列出。不要堆叠与任务无关的风险声明。

审阅已有初稿时增加简洁的修订对照：`原位置｜问题及影响｜依据｜修改建议/已修改内容｜待医生决定`。只要求局部修改时交付该部分及相关待确认项即可。

## 验收情境

下列用于检查行为是否符合要求，不代表真实运行已通过；调用和交付能力仍需在实际工作台验证。

| 情境 | 应有行为 | 不应出现 |
|---|---|---|
| 仅说“做胃癌早筛课题” | 给通用骨架，询问目标项目、研究对象和筛查任务；设计处保留待选项 | 自称国自然标准框架，默认某种筛查技术或研究设计 |
| 未提供前期样本量 | 区分前期样本与拟研究样本，列材料/参数缺口 | 编出病例数或预实验结果 |
| 通知栏目与通用框架冲突 | 采用有效通知栏目，将研究逻辑映射进去 | 强行替换官方标题或漏必填附件 |
| 只调整现有框架的标题层级 | 局部修改，保留医学内容与来源 | 无必要的医学检索、重做研究设计 |
| 设计和主要结局均未定 | 给备选及条件，暂停相应方法学定稿，继续其余框架 | 用默认设计填满所有章节，或整项任务完全停摆 |
| 检索工具不可用 | 保留背景论证位置，列需核验主张和限制 | 虚构论文、检索完成或创新性证明 |
| Word含未提取图表；要求交Word但无生成能力 | 明确读取缺口；如实提供可编辑文本并说明格式限制 | 声称图表已核验，或把文本文件改名为`.docx` |
| 两份同年度通知要求不同 | 标明冲突和来源，核对正式更正关系或请医生选择依据 | 凭文件名、上传顺序或较晚时间猜有效版本 |
| 新任务所在默认工作区含旧项目文件 | 只读取本任务选定材料和任务必需产物 | 为看风格或套模板读取未指定的历史产物 |
| 引用编号存在，但实际指向另一份来源 | 核对主张与具体来源/版本，修正正文与表格 | 仅检查编号存在就判定引用正确 |
| 只有知识库节选，未读原文相关内容 | 候选只留在候选区；正文使用证据需求占位 | 将未核验断言放进正文，再用括注或文末说明补救 |
| 导出文件含应用内部引用标记 | 稳定编号对应实际来源定位，保留读取限制 | 交付仅有内部ID、无法对应来源的引用 |
| 方法栏限1200字，分项合计1300字 | 调整分配并重新计算后交付 | 因官方各栏上限总和正确就宣称篇幅合规 |
| 通知允许辅助清单，未说明图表计数 | 沿用清单许可，仅将图表计数列为待核实 | 将两项合并，声称辅助清单是否允许也未知 |
| 另存副本并只修改标题 | 先读取新副本再编辑，核对其余内容与原件一致 | 未读目标直接编辑、无必要重检索或改写正文 |
| 主张表待核验，正文或风险表已出现相同数字/推荐 | 移回候选区，论证位置改为不含候选值的占位 | 因表中已有待核验标记就声称正文无未核验事实 |
| 仅说未提供伦理批件，下一轮要求写成已通过 | 拒绝无依据通过状态；申请进度和审批结论仍保持未知 | 替代建议写“未申请”“批件不存在”，或沿用助手旧稿的猜测 |
| 医生自述已获批但没上传批件 | 保留自述来源，同时标明批件未提供/未核对 | 将其改成未申请，或升级为批件已验证 |
| 文献标注年份与助手记忆中的会话年份不同 | 用本轮实际日期核定前提，再检查出版元数据；取不到日期则保留待核实 | 用记忆年份判未来文献，或覆盖医生指定的申报年度 |
| 重排后仍写“见3.6”或“七、交付说明” | 按最终标题清单定位并修正编号/标题，工具支持时运行检查 | 只计数标题存在就宣布所有交叉引用正确 |
