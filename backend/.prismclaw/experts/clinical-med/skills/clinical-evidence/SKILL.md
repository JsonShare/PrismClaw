# 临床证据纪律

本技能是横切的纪律层：不承接场景分流，场景入口由 `clinical-assessment-workflow` 与各专项技能承接；被调用时按下列纪律约束其输出。药物与过敏的确定性校验走 `prescription-safety-workflow` 的脚本，本技能脚本只处理条件-行动规则账本。

凡输出涉及用药、阈值、复查或操作时限、指南推荐、鉴别诊断与患者话术，均按本技能执行。用户明确指定交付格式时优先其格式，但不降低本节证据要求。来源核查过程留在执行中，不作为正式答案的前言。

## 六条纪律

1. **结论先行，保留不确定性。** 默认以「结论：」开头，先回答当前问题，再给依据、适用条件与必要建议。证据不足时把不确定性写进结论，不另起「核验说明」式的收尾区块。
2. **三类内容分离。** 内部逐句区分用户给定事实、疾病或证型的一般特点、临床推断。患者话术只把已给事实写成患者的现有情况；一般特点用「这类情况可能……」；待核症状用「如果……」，不能套入患者。行为后症状变化保留先后关系，不据此断言已证实因果。
3. **原文优先，版本先定。** 药物、阈值与就医时限先读原文再写；检索摘要只用于定位，不把摘要、书目或生成总结当已核全文。用户指定指南组织或年份时先定位该版本，补充来源单列名称、版本与适用范围，不把不同来源的数字拼成一条规则。读不到原文时删去非必要数字，核心缺口明确列待核。
4. **关键主张逐句绑定。** 会改变处置的具体主张（操作步骤、量表条目处理、阈值、鉴别要点）须绑定本轮已读且直接支持该句的原文位置。多个疾病或亚型分行核对，不合并外推。已读来源未覆盖的定点补核一次；仍无依据则删去非必要主张或列必要缺口，不以「临床经验」保留未经核实的具体处置。
5. **双受众同源。** 医生分析与患者话术从同一条已核实条件行派生；通俗改写保留原来的医学对象、药物类别与操作，不用相似名称替换。每份可独立使用的材料都自带适用前提、禁忌与求助触发，不靠另一份长文补救。患者首次出现的必要术语在原句用日常语言解释。
6. **终稿独立审阅。** 正文、表格与患者话术形成后，按 `references/output-review.md` 检查实际成品。确定错误必须修改，不用「待医生确认」掩盖；文件与渲染只报告实际完成状态。只交一份整合结果，不先发未核草稿再补零散修订。

## 检索分层

独立知识问答（一个药、一个指南版本、一篇文献、一个概念或指标）默认先检索再答，不凭自身记忆给出剂量、阈值、适应证或文献结论；用户不必说「搜」或「查」。

按层次取用，上一层能定案就不进下一层：

1. **已选定的本地材料**：用户本轮给的文件、科室材料与已入库资料。引用前定位到页码、表号或段落。
2. **知识库检索**：`knowledge_search` 查已入库的指南、药品说明书与院内资料。
3. **广域检索**：`WebSearch` 定位来源，`WebFetch` 取正文；摘要只作定位线索，不当已核全文。
4. **原文读取**：PDF 走 `workbuddy-pdf`，图片与扫描件走 `ViewImage`，逐条回对原文。

退化规则：某层不可用时说明具体限制并继续用可用层次，不伪装调用、不据缺失层编造结论。全部检索层都不可用时明确告知无法核实，把相关结论降级为「未核」并列出需人工核对的具体项，不改写成肯定表述。

## 危急信号

输入出现危急标记或明确快速恶化线索时，先指出具体线索、原始时间与已知处理状态，单列在常规建议之前；未知风险不写成已排除。同一信号是否需立即处置取决于严重程度或伴随表现时，写出升级条件。当前安全无法确认时，联系本人、请可到场者查看、院内上报及请求急救或警方协助查找同时启动，不按时间段依次等待，也不以「已确认发生危险」作为请求协助的前提。

## 条件-行动核查

用户指定方法或框架、要求分层随访、规则含 AND/OR 或版本冲突时，读 `references/condition-action.md`。指定方法先核原名、出处、用途与版本；同名异义或未定义时挂起依赖项，不自行编造步骤，也不因疾病指南未提及就断言方法不存在。
指定版本与原文定位读 `references/guideline-version.md`。接受稿、译文或转载不冒称已核正式版；规范题录链接与实际读取文件不同时同时保留两者。

## 确定性校验（明确联用核查时必做）

只在明确实际或拟联用方案、或确需结构化一致性审计时启用；通用风险清单与简短咨询不强制生成账本。脚本仅用 Python 标准库、离线，不联网。

- `scripts/condition_table.py --plan <plan.json> --format markdown`：用互斥分支生成条件规则段与走读表。工具只处理已解释为低／区间内／高／无法判定的状态，不提供阈值、不评价真实患者。
- `scripts/validate_ledger.py <账本.json> --tables <报告.md>`：检查 schema 2 账本并输出可编辑核心表；`--check-report <报告.md>` 比对最终报告核心块。

退出码：0 表示结构与指定数据块检查通过，1 表示发现不一致，2 表示文件或格式错误。脚本只检查记录不变量，不验证来源真实性或临床适用性，最终仍须人工回对原文。旧 schema 1 拒绝加载，不自动升级。详见 `references/ledger-check.md`。

## 边界

所有输出为草稿，不构成诊断或处方。来源不明的结论标注 `[待核验]`，不把模型推断包装成已核实事实。医学结论由发起医师确认，不代确诊、开方、执行医嘱、签署或外发。
