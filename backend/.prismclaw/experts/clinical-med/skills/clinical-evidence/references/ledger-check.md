# 账本与机械校验

用于明确的实际联用核查，或确需结构化一致性审计的交付。通用风险清单、备选比较和简短咨询直接按入口规则核对，不因多个药名或引用而强制生成账本；真正同用的药物集合仍完整核查。账本与报告写入当前任务目录，不含无关身份资料；脚本仅用 Python 标准库、不联网。

## 用法

```text
python3 scripts/validate_ledger.py <账本.json> --tables <报告.md>
python3 scripts/validate_ledger.py <账本.json> --check-report <报告.md>
python3 scripts/condition_table.py --plan <conditions.json> --format markdown
```

退出码：0 通过结构或指定数据块检查，1 发现不一致，2 文件与格式错误。失败先修正，不能只改标签凑通过。Python 不可用时人工核对并说明，不能声称脚本运行。

## 账本纪律

顶层 schema_version 必须为 2；旧结构拒绝加载，须重新对照来源建立主张级绑定，不自动升级为已核验。

事实字段：对象与字段唯一；provided 值为原文字符串且有引文，missing、conflict、unreadable 值为 null；冲突保留至少两侧引文。缺项表只编码影响当前任务的缺项。时间区分 current 与 historical，历史截止必须有明确来源与引文；clock 模式只用于同一时段，并给出可比较依据，不跨日强行排序。

来源与主张分开记录。来源字段包括定位方式、实际工具引用、读取层级、实际读到的最小相关片段与限制；读取层级为正文、节选、摘要、生成、转引或不可读。主张状态为已核验、线索或不可读，每项支持须包含来源、依据类型、引文与位置，引文必须存在于来源片段中。摘要或生成答案不能单独认证医学主张；读取层级不能代替主张支持关系。

用药对按无序对记录一次，成分与复方按工作流核对。检索状态为已检索、未检索或受阻；受阻须给真实原因并披露。未检索阻止交付；找到结果必须关联主张。证据缺口与病例待核项显式列表，剩余缺口给出实际停止理由，不用「以后可查」代替。

## 检查边界

统计按关联主张推导，不手工改计数。`--tables` 输出可编辑 Markdown，含时间分区、事实与缺项、主张原文及支持关系、逐对状态与来源定位，外有固定标记块。`--check-report` 要求唯一完整块与当前账本生成结果一致，能发现改数、改状态、删主张或旧块未同步。

它不检查块外语义，也不验证源文真实性或临床适用性。最终仍须人工回对源文，特别是用药阶段、已知变缺项、转引升级与自加医学解释。HTML 转换可保留内容但不保证标记与格式，需独立检查关键表格与末尾。
