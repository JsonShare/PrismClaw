# 病历照片与扫描图读取

仅适用于本次明确选定的静态JPEG/PNG/WEBP附件，以实际解码格式为准，不扩展读取目录，不改变原件。多帧来源不默选第一帧，需要明确选定可核对的静态来源。先看全图、记录尺寸和原文行序。数字、日期、药物、左右侧、病情变化、检查结论和引用照片等信息逐行清点；字段标题清楚而后半行不清时，保留可读片段及具体位置，不把整行当成未提供。

字密、字小或局部不清时，围绕完整短句及上下文选择像素框，调用本包已测试的阅读辅助入口：

```text
<同一已确认Python> <技能目录>/scripts/inspect_region.py --input <本次附件> --box <左,上,右,下> --scale 2 --out-root <本次工作区/reading-aids>
```

坐标为原图存储像素，右/下边界不包含在框内，必须在原图范围内；不自动按EXIF旋转。输入上限25MiB及4000万像素，放大倍数1–4，输出上限1600万像素。需要时先用已确认解释器的Pillow读取本次文件尺寸及EXIF方向，不猜坐标。返回唯一目录中的region.png与region.json；用当前实际可用的图片读取工具查看region.png，再与全图核对眼别、列和行归属。WEBP解码不可用或来源损坏时明确保留读取缺口，不安装工具或改用其他患者来源。

裁图必须包含所核原句的行首、行尾、否定/限定词及完整末行，并留足上下文边界；跨行的结论一起查看。若裁图切掉文字，回到原图扩大或重取区域，不能用残缺裁图宣称复核完成。只有查看了实际输出图并与全图对上，才能将文字登记为已核；程序退出码、OCR候选或放大倍数不代替此检查。

输出仅裁切并以最近邻重复已解码源像素，不插值、不增强、不生成新文字，保留原件SHA256、实际格式、方向及框坐标、倍数和输出指纹；这不恢复压缩前的拍摄像素。它只帮助阅读，不能证明识读正确。重点短语读成不通顺措辞或OCR与图面冲突时复核上下文，不照录一个罕见词就宣称已核实，也不凭常见医疗搭配猜成正确词。复核后仍不能确定的部分明确待核，尤其不能生成可执行用药指令。

辅助图留在本次工作区，不当作新的医学检查或替换原件交付。纯内联文字整理分支仍不调用工具；源文成稿与发布协议保持原约定。

## 关键动作的独立文字核对

截图中的检查名称、所见与治疗动作容易被相邻词或遮挡混淆。macOS且现有环境已提供Swift时，使用本包只读本地OCR作独立候选核对，不安装工具、不外发图像：

```text
swift <技能目录>/scripts/ocr_image.swift <本次选定图片或上述局部阅读图> > <当前工作区>/ocr-candidates.json
```

返回原图指纹、坐标及至多3个文字候选，关闭语言纠错。坐标为按EXIF方向解释后的左上角归一化坐标，与不旋转的裁切坐标不同；EXIF不是1时不可直接套用。脚本只接受JPEG/PNG，限制35MB和4000万像素。没有Swift或识别失败就保留图面可读部分与缺口，不安装、不用其他患者资料替代。

WEBP来源先使用上述局部阅读入口生成region.png，再将此PNG交给OCR，不直接传WEBP。此时OCR指纹与坐标属于局部PNG；通过region.json的regionSha256、sourceSha256、boundsPixels和scale映射回原件存储像素，不能冒称OCR直接核过原件。局部PNG不带原件EXIF旋转；与全图核对时仍按原件方向辨明行列。

OCR不是医学确认，置信度高也不证明已实施某治疗。候选与图面冲突、动作字被遮挡或只有检查所见时，不把推断的治疗写进可粘贴草稿。先保留确实明确的检查事实，完整术式及是否实施列为中性待补。只有在实际原文中同时明确看到动作和实施状态，才能写“行/予/已完成”该处置；“检查提示某病变”不能改成“切除/活检/治疗了某病变”。草稿正文与前后说明遵循同一标准。

## 交接临床分析

只交接当前问题需要的已核原句、原图行/区域定位及具体读字缺口；纯转录不生成诊断。检查所见与报告印象分别保留，不能只摘所见而漏掉可读印象。报告明确给出病变名称时写“原报告提示……”并保留全称，再另列临床解释或确证限制；病因未定不使该所见降为猜测，二次确证也不反向抹掉已写明的报告结论。仅信号或形态描述不自动证明物质性质、病因或新旧。原图未写的阴性不能由常识补入。症状、支持治疗或处置的先后关系按原句保留，不从处置频次补出症状、反复失败或确定因果。完成核对后由临床任务复用这些事实继续分析，不重复加载或自由另造一套病例摘要。
